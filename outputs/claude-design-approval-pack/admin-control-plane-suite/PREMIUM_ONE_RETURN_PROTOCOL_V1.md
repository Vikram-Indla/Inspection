# Premium one-return protocol

## Objective

Produce a sponsor-reviewable premium design package on the first return. Independent review remains mandatory, but it produces either `READY_FOR_SPONSOR_REVIEW` or one consolidated correction brief. Piecemeal correction rounds are prohibited.

## Why earlier returns multiplied

The CD-004 visual direction was not the principal failure. Returns multiplied because the package contained cropped exports, guessed schema fields, vague code paths, incorrect research-ID mapping and unverified evidence declarations. These are deterministic preparation failures, not creative exploration failures.

## Division of responsibility

Codex freezes before generation:

- contract and screen ownership;
- exact runtime facts and known blockers;
- source schema names;
- candidate implementation paths;
- research-source ID mapping;
- required evidence names, dimensions and disclosure;
- review gate and return marker.

Claude Design owns:

- premium information architecture;
- three serious composition hypotheses;
- the selected visual system and signature interaction;
- Arabic-first RTL composition;
- dark/light and constrained-width equivalence;
- accessible interaction specification;
- accurate packaging of the frozen facts.

Claude Design must not rediscover or rewrite frozen runtime facts. If source evidence contradicts one, it must flag the contradiction and keep the affected leg blocked.

## First-return gate

Before returning, Claude Design performs one silent preflight over every file and frame:

1. Visual: premium, inspection-specific, no generic SaaS/CRUD composition.
2. Truth: no invented data, policy, provider, lifecycle or successful action.
3. Paths: every component and change has one literal repository path.
4. Wiring: every row is complete or explicitly `HANDOFF_BLOCKED`.
5. Arabic: native RTL hierarchy with realistic long content and stable mixed-direction identifiers.
6. Theme/responsive: equivalent meaning in dark/light and at 1024px.
7. Accessibility: keyboard, focus, semantics, announcements, non-color status and reduced motion specified.
8. Evidence: standalone frame exports at declared dimensions; no canvas crops or neighbouring frames.
9. Manifest: dimensions and SHA-256 are measured from delivered files, not typed from intent.
10. Research: binding source IDs are unchanged.

Any failed item must be repaired before the package is returned.

## Review and correction policy

- Independent review checks the entire package once.
- All P0/P1 issues are consolidated into one correction prompt.
- The correction may repair defects but may not reopen the selected design direction unless the review proves a P0 usability, truth or contract failure.
- After that single correction return, unresolved P0/P1 blocks sponsor approval and is escalated as a decision—not converted into repeated prompt iterations.

Status model:

`GENERATION → FIRST_RETURN → INDEPENDENT_REVIEW → READY_FOR_SPONSOR_REVIEW`

or, when necessary:

`GENERATION → FIRST_RETURN → INDEPENDENT_REVIEW → ONE_CONSOLIDATED_CORRECTION → FINAL_REVIEW → READY_OR_BLOCKED`
