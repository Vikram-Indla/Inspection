# Post-Approval Vertical Slice SOP V4 — Quality-Preserving Wiring

1. Record the exact sponsor-approved frames, states and P0/P1 corrections. Freeze the accepted page decision and family inheritance ledger.
2. Re-read current code and contract. Reconcile route, screen identity, lifecycle ownership and writable state before authorizing any edit.
3. Trace every interaction through UI, guard, canonical transition, data/provider, RLS, audit, side effect and test. Missing or contradictory legs are `HANDOFF_BLOCKED`.
4. Run a pre-implementation truth review for authorization, input preservation, stale/concurrent state, idempotency, partial failure, package/version immutability and notification/provider semantics.
5. Compare the accepted design against the actual runtime data fields. Remove or explicitly mark any unsupported recommendation, score, availability, location, travel, skill, capacity or override signal.
6. Obtain explicit implementation authorization for the exact vertical slice, files, migrations/policies, tests and rollback. Design approval alone is insufficient.
7. Implement the smallest coherent slice on the safe non-main dirty worktree without weakening protected behavior or overwriting unrelated changes.
8. Prove type/build/unit checks and real happy, invalid, unauthorized, stale, concurrent, double-submit and partial-failure paths. Reconcile UI result with records, transition, audit and side effects.
9. Prove Arabic-first RTL, mixed-direction content, dark/light, desktop/narrow, keyboard/focus, screen-reader alerts/status and reduced motion.
10. Run a visual regression comparison against the accepted family baseline and the approved page frames. Reject generic substitutions and shell drift.
11. Codex independently issues a Pass/Correct/Block certification. Any unevidenced P0/P1 remains open.
12. Sponsor separately records runtime acceptance. Only then may the screen slice be treated as accepted and complete.

No UI-only completion claim. No fake destination or data source. No global-shell redesign inside a page slice. No silent route or screen-ID reassignment.
