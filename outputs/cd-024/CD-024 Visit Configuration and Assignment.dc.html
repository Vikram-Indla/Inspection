Keyboard · focus · status · reduced motion (R1: plain-table model)
Model: plain semantic table — no roving focus, no ARIA grid. Every native control (config selects/inputs, each row's method/inspector select, "Review evidence" buttons, scope buttons, publish) sits in the normal tab sequence. The ledger updates on row focusin (any control inside the row) or explicit "Review evidence" activation — no Enter/Escape widget behavior is claimed. Entry: main heading; exit: publish button. Submit failure: focus moves to the error summary (role=alert, tabindex="-1"); each entry is an anchor to its control; correction clears the entry and keeps focus on the corrected control (see 4i). Status region (polite): "loading 12 selected factories…", "scope reduced — 10 of 12", "publishing 10 visits…", success. Alerts (assertive): conflicts, re-check failures, transaction failure. Conflict/selection always glyph + text, never color alone. Reduced motion: no highlight transitions or scroll animation; the ledger swaps content instantly.
Research ledger — adopted / rejected
Microsoft Field Service — schedule board & manual scheduling (learn.microsoft.com/en-us/dynamics365/field-service/work-with-schedule-board): the schedule board is a dispatcher surface for explicit manual booking over known bookings; it displays existing bookings, it does not infer availability. Adopted: manual assignment decided over known assignments rendered as text evidence (exact visit + window). Rejected: the board/timeline visualization — it reads as availability, which Saqeel cannot verify.
Microsoft Field Service — resource types (learn.microsoft.com/en-us/dynamics365/field-service/scheduling-resource-types): scheduling behavior depends on which resource attributes are actually modelled; a resource only supports what its type carries. Adopted: candidate evidence limited to attributes Saqeel verifiably has (role membership, known assignments); everything else is a named "Not evaluated". Rejected: skill/territory/location/hours attributes — no Saqeel source.
W3C ARIA APG — grid (w3.org/WAI/ARIA/apg/patterns/grid/): a composite grid requires the full managed-focus contract (focus entry/exit, arrow-key navigation, Enter/F2/Escape, screen-reader behavior). Adopted as the rejection criterion: this design uses a plain semantic table with native tabbable controls instead. Rejected: any roving/one-tab-stop behavior without that contract.
W3C ARIA APG — listbox (w3.org/WAI/ARIA/apg/patterns/listbox/): custom listboxes carry selection-model and screen-reader caveats that native select elements avoid. Adopted: native selects for method/inspector, in the normal tab order. Rejected: styled ARIA listboxes.
GOV.UK Design System — error summary (design-system.service.gov.uk/components/error-summary/): on failed submit the summary receives focus, each error links to its control, entered values are preserved; permission failures are not field validation. Adopted verbatim (4i). Rejected: nothing material.
Saudi DGA — web accessibility for people with disabilities & the elderly (dga.gov.sa/en/digital-knowledge/web-accessibility-disabilities-and-elderly-people): government services must stay operable for disabled and elderly users — keyboard operation, clear language, adequate control sizes. Adopted: ≥44–48px targets, glyph+text status (never color alone), plain-language failure copy. Arabic-first is NOT sourced here — it is the binding Saqeel baseline (DEC-011).
