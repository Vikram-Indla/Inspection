# Dashboard external-dependency ledger

External unavailability is an `OPEN_EXTERNAL` acceptance state, not an internal
engineering defect. Dashboard code must consume persisted, RLS-filtered
Supabase records; it must not call a third party during KPI calculation or
silently replace an unavailable provider with synthetic production truth.

## Acceptance status

- Map rendering/provider certification: `OPEN_EXTERNAL`.
- Senaei live factory/licence synchronization and freshness: `OPEN_EXTERNAL`.
- Health Score source contract: `OPEN_EXTERNAL`.
- Strategic AI Summary and Operational AI Nudges: `OPEN_EXTERNAL`.
- Internal KPI calculations over already persisted RLS-visible records remain
  independently testable and must not be held open merely because a provider is
  unavailable.

No Dashboard stub is presented as live. Existing repository fixture providers
are non-production-gated, deterministic, explicitly identify themselves as
`stub`, and remain outside the Dashboard KPI truth path.
