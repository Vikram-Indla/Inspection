## Premium design principles

1. Calm operational hierarchy: orient the user to job, role, scope, lifecycle state, blocker, evidence and one safe next action.
2. Saudi government authenticity: use approved Ministry context, domain language, Hijri/Gregorian handling where governed, and a native-reviewed Arabic experience without decorative cultural shorthand.
3. Truth before polish: distinguish live, projected, last-known, simulated, fixture, unavailable, stale and partial-source states.
4. Evidence-led decisions: keep source, version, capture time, audit lineage and immutable state adjacent to regulatory actions.
5. Fail closed: provider, permission, package, policy and synchronization gaps must never look successful.
6. Field confidence: preserve offline, sync, conflict, evidence, geofence and immutable-submission semantics on iPad.
7. Accessible at workflow level: certify keyboard, focus, screen reader, zoom/reflow, target size, status announcements and Arabic comprehension across complete tasks.

## Foundations

- Preserve the current Government Foundation token intent, then add semantic tokens for lifecycle, evidence confidence, provider state, data freshness, sync state, conflict, immutability, projection and fixture provenance.
- Use a bilingual Arabic/Latin scale with stable numerals, generous Arabic line height, tested truncation and no mixed untranslated fragments.
- Use an 8-point spatial rhythm with density modes governed by task and viewport—not arbitrary per-page compression.
- Status must combine text, icon and color. Dark theme must retain regulatory contrast and map/chart legibility.
- Motion is restrained and informative; no animation may obscure a transition result, sync state or evidence capture.

## Shell, navigation and account context

- One shared shell must expose persona, governed scope, locale, theme, notification state and account identity consistently.
- Navigation groups follow user jobs and journey stages. Current destination, breadcrumb and lifecycle context remain explicit.
- Global destination search and page entity search are visibly different.
- Account identity cannot clip in Arabic or at 412 px. Accessible names for repeated controls must remain unique.
- Role display is informational; the interface must not imply role switching where authorization does not allow it.

## Page composition

Every operational page uses: decision header; scope/freshness strip; primary work region; contextual evidence/audit/help rail when useful; and a state-aware action region. One primary action is visible. Irreversible actions are separated and summarize affected objects, version and consequence. Loading reserves layout; empty and error states explain cause, scope and permitted recovery.

## Tables, lists and selection

- Use bounded pagination or virtualization at representative scale, sticky headers, stable row identity and preserved return position.
- Active filters, result count, selection count and cross-page selection semantics remain visible.
- Saved views never hide freshness or security scope. Bulk actions disclose partial-failure behavior before execution.
- Automated fixtures are visually and operationally separated from sponsor-quality representative records.

## Forms, validation and workflow

- Labels persist; required, optional, policy-blocked and provider-dependent inputs are distinct.
- Inline errors and a blocker summary point to recovery without discarding work.
- Draft, submitted, returned, approved, rejected and immutable versions are visually distinct.
- Canonical transitions and guards remain the only status mutation path. Submitted versions cannot become editable.

## Maps, dashboards and charts

- Maps provide explicit loading, zero-coordinate, provider-failed, partial and stale states. A stated record count must be verifiable on canvas or list.
- Projected route is never styled or worded as live GPS. Live, last-known and projected telemetry use distinct tokens and timestamps.
- Dashboard metrics expose definition, scope, period, freshness, target configuration and unavailable denominator states.
- Charts use accessible legends, tabular alternatives and RTL-aware reading order; visual embellishment cannot outrank operational truth.

## Evidence, media, audit and review

- Evidence cards expose type, source, capture time, uploader, linked object, sync state, integrity/immutability and privacy sensitivity.
- Media failure, permission denial, file-size limits and retry remain visible and recoverable.
- Review workspaces preserve immutable submissions, comparison provenance, changed-section navigation and reason-required decisions.
- Audit views use bounded timelines with actor, action, object, version, timestamp and reason; replay/provider limitations remain honest.

## Offline, sync and conflict

Use explicit states: saved locally, queued, syncing, synced, conflict, failed and blocked. Never silently overwrite server changes. Returned corrections unlock only governed sections. Pre-submit summarizes missing mandatory answers, evidence, conflicts and network state before creating an immutable version.

## Arabic, RTL, accessibility and responsive behavior

- Native Arabic review is mandatory for domain terminology and full task comprehension.
- Mirror spatial layout while preserving logical order for identifiers, dates, coordinates and mixed-script values.
- Certify EN/LTR and AR/RTL in light/dark at 1440 desktop, tablet portrait and 412 px.
- Maintain visible focus, logical landmarks, unique names, WCAG 2.2 target sizing, announcements and complete keyboard workflows.
