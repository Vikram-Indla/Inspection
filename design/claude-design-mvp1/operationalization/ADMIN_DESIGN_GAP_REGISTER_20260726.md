# Admin design gap register — 2026-07-26

Purpose: repo-aware production brief for the ten `admin-*` board cards. This is a design gap register, not permission to remove or weaken existing behavior. Claude Design must preserve RBAC/RLS, route guards, deep links, maker-checker transitions, immutable versions, audit history, truthful source states, and keyboard/responsive behavior.

Scoring: impact and confidence are each 1–10. Rank is ordered by user harm, authorization risk, workflow blockage, then visual quality. `P0` blocks safe production use; `P1` blocks a complete admin workflow; `P2` is a material usability/polish gap.

## Top-20 Claude Design production shortlist

Claude Design should implement these as screen/system changes, not respond with prose:

1. Role-filter the entire admin shell and hide unauthorized routes/actions.
2. Replace the long hanging rail with grouped progressive navigation, search, pinned/recent items, and mobile drawer.
3. Establish one scroll container and a compact sticky context header; remove nested scrollbars.
4. Produce the Users/Roles capability matrix with inherited, allowed, denied, locked, override, and scoped states.
5. Produce the full delegation workflow with reason, time box, scope, review, revoke, and audit.
6. Build a visual form studio: palette, canvas, inspector, validation, preview, versions, and governed JSON.
7. Build an executable workflow studio: graph, guards, simulation trace, SLA outcomes, validation, and publishing.
8. Unify template/package IA and show version lineage, impact, maker-checker approval, and immutable publication.
9. Reframe execution settings as governed policy versions with dependencies, effective dates, impact, and staged activation.
10. Unify KPI definitions and dashboard configuration; add lineage, formula, target, bilingual labels, responsive preview, and source/error states.
11. Design dual-pin/geometry geofence authoring with synchronized coordinates, precision, keyboard access, and full audit.
12. Design integration truth states and SENAI/factory provenance, validation, partial failure, retry, and writeback.
13. Design trustworthy passkey/device enrolment, challenge, verified, revoked, failed, quarantine, and offline caveat states.
14. Design platform audit retention as explicitly unconfigured until governed values are approved.
15. Design localization review/publish with missing Arabic, variable/plural validation, comparison, and preview.
16. Design risk model factor/weight/threshold editing against `apps/web/src/lib/risk/model.ts`, with deterministic preview and no health/risk conflation.
17. Add scenario validation, impact preview, approval, activation, rollback, and immutable history for risk models.
18. Standardize staged/destructive actions: impact, reason, recent authentication where applicable, confirm, progress, and durable receipt.
19. Cover truthful loading, empty, partial, stale, validation, denied, conflict, offline, success, and failure states on every surface.
20. Deliver every screen in English/LTR and Arabic/RTL, light and dark, desktop/tablet/mobile, without removing any current route or governed behavior.

## Cross-cutting design acceptance matrix

Every updated admin page must pass every applicable row. A thumbnail or static happy-path frame is not acceptance evidence.

| Dimension | Required variants | Acceptance |
|---|---|---|
| Language and direction | English/LTR; Arabic/RTL | Native directionality, mirrored layout where semantic, correct icon direction, no clipped or duplicated bilingual headings, locale-aware dates/numbers, translated control/status/error text. |
| Theme | Light; dark | Token-based surfaces/text/borders/status/focus; AA contrast for normal text and interactive states; charts/maps retain meaning without color alone. |
| Viewport | Desktop 1440; tablet 1024/768; mobile 390 | No hanging panels, accidental horizontal scroll, nested body/rail scroll, obscured actions, or truncated critical values; tables have an intentional small-screen mode. |
| Authorization | Full admin; scoped admin; reviewer; read-only; denied | Navigation, actions, fields, and data scopes match authority. Hidden, disabled, locked, read-only, and denied remain distinct and explainable. |
| Data truth | Live; loading; empty; partial; stale; degraded; failed | No invented activity or counts. Preserve last known data where safe, label freshness/source, expose retry/details, and never turn a partial failure into “no records.” |
| Editing | Pristine; dirty; validating; invalid; saving; saved; conflict | Field-level and summary errors, unsaved-work protection, deterministic retry, conflict comparison, and no silent overwrite. |
| Governance | Draft; review; approved; scheduled; active; retired/revoked | Owner, actor, reason, version, effective time, impact, approver, immutable history, and canonical actions are visible where applicable. |
| Destructive/security action | Ready; confirmation; in progress; success; failure | Exact scope/consequence, reason, typed or recent-auth confirmation where applicable, idempotent progress, and durable receipt. |
| Accessibility | Mouse; keyboard; screen reader; zoom 200%; reduced motion | Logical focus/order, visible focus, named controls, announced validation/status, keyboard-equivalent map/builder operations, motion not required for meaning. |
| Deep links | List; selected detail; editor; return | Stable URL/state, refresh-safe selection, meaningful title/breadcrumb, back returns to prior filters/page, unauthorized deep link fails safely. |
| Builder/map complexity | Normal; invalid; large; degraded provider | Canvas and inspector remain usable; zoom/pan/selection are keyboard-accessible; performance state is truthful; raw representation is secondary and recoverable. |
| Audit/localization | Summary; immutable detail; export | Human-localized labels plus preserved immutable IDs/raw values, actor/source/correlation, before/after, and scoped export with no fabricated retention policy. |
