## Shared contracts for every page

- **States:** EN/LTR and AR/RTL; light and dark; 1440 desktop, 1024/768 tablet, 390 mobile; loading, empty, partial/stale/degraded, failed, denied/read-only, and live data where applicable.
- **Shell:** role-filtered navigation and actions; one content scroll container; stable deep links and return state; compact sticky context header; keyboard and 200%-zoom support.
- **Mutation:** pristine, dirty, validating, invalid, saving, saved, conflict; reason and impact where governed; canonical transition only; durable receipt; immutable published/submitted history.
- **Truth:** no invented counts, activity, retention, thresholds, providers, SLA values, weights, or geofence values. A missing contract renders `Not configured`/`Unavailable`, not a plausible default.
- **Security:** UI hiding is not authorization. Existing server guards, RLS, role checks, scope checks, and audit writes remain authoritative.

## Backend and product-contract gaps

These items are not safe to “complete” through front-end implementation alone:

1. **Delegation (hard block):** no route, schema, RLS, actions, grant intersection/escalation rules, expiry/revoke enforcement, audit contract, or tests.
2. **Audit retention:** no approved retention value or governed persistence/approval contract. Display unconfigured.
3. **Passkey/WebAuthn:** no proven challenge, credential binding, verification, revoke and audit lifecycle behind the current design.
4. **Device governance:** stable detail route/activity source, quarantine semantics, offline propagation, expiry and risk signal are incomplete.
5. **Geofence governance:** dual-pin meaning, authoritative geometry representation, precision/provider policy, approval/version lifecycle and conflict rules are incomplete.
6. **Integration operations:** retry, pause, resumable import, duplicate strategy, rejected-row artifact, writeback and scheduling need live action/storage contracts.
7. **Maker-checker/versioning:** packages, forms, workflows, execution policy, KPI dashboards and risk models cannot share a decorative generic status model; each needs canonical persisted transitions and immutable-version enforcement.
8. **Access review and overrides:** reviewer assignment, due dates, signed attestation, expiry enforcement, conflict rules and revoke semantics need server contracts.
9. **Dashboard editor:** breakpoint persistence, collision behavior, undo history, audiences and publish transition need an accepted layout schema/actions.
10. **Localization:** the 27 missing Arabic KPI titles require authoritative translations or an explicit fallback; do not machine-invent production labels.
11. **Notifications:** recipient resolution, test delivery, channel degradation and quiet-hours semantics require actual provider/action behavior.
12. **Operational policy:** do not choose thresholds, SLA clocks, effective dates, risk weights, missing-data rules, geofence radius/precision, providers or retention.

## Safe implementation sequence

1. **Shared shell and truth states:** role-derived navigation, one-scroll layout, header hierarchy, RTL/theme/responsive tokens, denied/read-only and data freshness patterns.
2. **Read-only information architecture:** landing cards, definition/detail rails, source/status labels, breadcrumbs/deep-link preservation, existing audit history.
3. **Existing mutation hardening:** field errors, summaries, dirty/leave protection, confirmation, progress and server-result receipt around actions that already exist.
4. **Existing builders:** progressively enhance forms/workflows/packages without changing their accepted payloads or canonical transitions.
5. **Domain surfaces:** execution, KPI, data, access, devices, GIS and risk, each constrained to its current schemas/actions.
6. **Contract-gated capabilities:** delegation, new approval/version lifecycles, passkey binding, geofence semantics and integration writeback only after backend/product contracts and negative tests exist.

## Minimum acceptance-test additions

- Parameterize every touched page for `en/LTR × ar/RTL × light/dark` and desktop/tablet/mobile.
- Assert scoped personas cannot see unauthorized navigation/actions and cannot access the same route directly.
- Assert partial/stale/failed sources never become false empty states.
- Assert dirty/conflict/invalid mutations do not overwrite server state.
- Assert all security/destructive operations include reason/scope, use canonical actions, and expose durable success/failure.
- Assert active/published/submitted versions cannot be edited directly.
- Assert browser refresh preserves supported deep-link selection and unauthorized deep links fail safely.
- Assert risk scoring uses `src/lib/risk/model.ts`/server actions and never platform-health proxies.
- Add explicit blocked/unsupported assertions for features whose backend contracts remain absent, especially delegation and WebAuthn.
