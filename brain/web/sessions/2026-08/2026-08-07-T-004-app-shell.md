## Decisions

**1. `x-pathname` already existed; no new header was added.** The brief asked for
`response.headers.set("x-saqeel-pathname", …)`. Two problems. First, a *response*
header is not readable from `headers()` in a Server Component — that reads the
**request** headers. Second, `src/middleware.ts:51` already does exactly the
right thing: `requestHeaders.set("x-pathname", request.nextUrl.pathname)`,
propagated through `NextResponse.next({ request: { headers } })`. Adding a second
header carrying the same value would have been duplication with a worse name. The
rail reads `x-pathname` in `features/shell/queries.ts` and computes
`aria-current` server-side, so **the fallback in §6.1 was not taken** — the entire
rail is a Server Component with no `usePathname`.

It also matters that `x-pathname` is set *before* the `/admin/regulations` →
`/compliance` rewrite, so it carries the URL the user is actually on, which is
what active state needs.

**2. Active state is `isShellRouteCurrent`, unchanged.** The existing function in
`lib/shell-navigation.ts` encodes real rules (`/dashboard` exact, `/operations`
prefix, query-string hrefs exact). It was reused verbatim rather than
reimplemented, because "zero behavioural change" means the highlighted row must
not move on any route.

**3. Eight client islands, not five.** The brief's budget assumed a topbar of
search / bell / user / theme. The real one also carries a **locale toggle**, a
**date + region scope filter** that writes `searchParams` consumed by
`/dashboard` and `/operations`, and a **⌘K admin palette**. Building only the
listed files would have silently deleted three working controls, which "no user
lost access to anything" forbids. They were rebuilt as
`shell-locale-toggle`, `shell-scope-controls` and `shell-admin-palette`.

Per-route island counts are lower than eight: the palette only mounts on
`/admin/**`, and search + scope only mount off it. A `/dashboard` first paint
carries rail-toggle, search, scope, locale, theme, bell, user-menu, mobile-nav.
Reducing this is a product decision about which controls survive, not a
refactor — parked in the tracker.

**4. `<main id="main-content">`, not `id="main"`.** §5.4 asked for `main`.
`e2e/ui-compliance-runtime.spec.ts` asserts `main#main-content` in three places
(lines 39, 60, 115) and the e2e suite was not in the editable file list. The
landmark and the skip-link target are what the rule is actually about, and both
are correct; the id string was kept so the suite stays green.

**5. The scroll model had to be copied exactly, not improved.** `.sq-pagehead` in
the frozen runtime sheet is `position: sticky; inset-block-start: 0`, and the 55
route files that still render the legacy `Shell` frame emit it. It worked because
`.sq-shell__main` was the scroll container. The first draft of `.sqx-shell` let
the document scroll and made the topbar sticky — which would have put two
elements at the viewport top on every one of those 55 pages. Corrected:
`.sqx-shell` is `100dvh` with `overflow: hidden`, `.sqx-shell__main` owns
`overflow-y`, and the topbar is a non-sticky flex sibling above it. This is the
single highest-risk thing in the diff and the reason to look here first if a
page renders wrong.

**6. Theme: three-way cycle without touching `ThemeScript`.** §5.1 wants
stored → `prefers-color-scheme` → dark, but `ThemeScript.tsx` was outside the
editable list, so the pre-paint resolver still only knows stored → dark. The
toggle writes **two** keys: `saqeel-theme-mode` (`system|light|dark`, the user's
actual choice) and `saqeel-theme` (the *resolved* value, which is the key
`ThemeScript` already reads). First paint therefore always finds an explicit
value and never flashes, including in system mode. A `matchMedia` listener keeps
system mode live. The gap — `ThemeScript` itself cannot follow the OS on a fresh
profile — is parked.

**7. Nav groups are native `<details>`, so disclosure costs zero JS.** `open` is
computed on the server: open when the group holds the current route, or when it
is not the pinned Administration group — the same rule the old `openGroups`
state used. One nuance: the old state persisted across client navigation because
the layout does not remount; the `open` attribute is re-derived per render, so a
group the user collapsed by hand may reopen on navigation if it holds the new
route. That is a behaviour *difference*, small and arguably correct, and it is
recorded here rather than hidden.

**8. The search dropdown is no longer portalled.** `ShellClient` portalled it to
`document.body` and measured its position on scroll/resize to dodge a compositing
bug (DR-36/DR-51) in the sticky `.sq-pagehead`. The new topbar is not that
element, so the panel is a normal absolutely-positioned child of a
`position: relative` wrapper. This removed two effects and all the measurement
code. **Unverified** — if the panel is ever clipped, the portal is the known-good
fallback.

**9. The AI entry is the topbar's one gradient CTA.** §4.2 reserves
`--sqx-gradient-cta` for "the one primary CTA in the topbar" without naming it.
The shell has exactly one promoted destination — `/ai/suggestions` — so it took
the gradient. Everything else in the chrome is flat, and the only other gradient
is the animated edge on the active nav item, as specified.

**10a. Owner revision, same session — AI accent and visible nav indicators.**
Three defects found on review of the built CSS, all confirmed by measurement:

  stop is `#0A2A18` — a separation of **1.02:1**, i.e. invisible. Light was
  1.07:1. Replaced with `--sqx-nav-active-bg`: light `#9FE7C4` (1.29:1 worst-case
  chrome separation, 6.63:1 with the accent label), dark `#1B4A31` (1.53:1

- Subgroup labels ("Inspection", "People & Access") had no fill and used

  `--sqx-nav-group-bg` (light `#DEE3DC` 1.18:1 separation, dark `#123A24`
  1.22:1) and `--sqx-text-secondary` (7.07:1 / 6.70:1) — muted would have scored
  4.30:1 on the dark fill, under the floor. A group holding the active route
  takes the same fill on its `<summary>`, and a subgroup containing the active
  row turns its label accent via `:has()`.

`data-current` on a nav group now means "holds the current route" for **every**
group, not only Administration — the styling is what makes the answer to "which
section am I in" visible, and it was previously computed but unused outside the
pinned group.

Five primitives added: `--sqx-neon-ai-light`, `--sqx-neon-ai-shade`,
`--sqx-green-tint-strong`, `--sqx-green-shade-strong`, `--sqx-ink-tint-group`.
Light's group fill reuses the existing `--sqx-warm-300`.

**The lesson for every later screen:** `--sqx-surface-accent` is calibrated
against `--sqx-surface-default`, not against the chrome gradient. Anything
placed on `--sqx-gradient-chrome` needs its separation measured against all
three stops, because the top stop in dark is close to several tint tokens.

**10b. Second owner revision — and the bug underneath it.** The reported symptom
was "the AI Insights text is not visible". The cause was not the AI colour at
all:

> `apps/web/src/app/saqeel-components.css:15` — `a { color: var(--text-link); }`

That sheet is **unlayered**, and an unlayered declaration beats a cascade layer
at *any* specificity. Every `<a>` in the new shell — the CTA label, every nav
item, search results, user-menu actions, palette results, breadcrumbs — was
rendering in legacy link-blue, and no amount of `color` in
`@layer sqx.components` could win. T-002's note that "the legacy sheets outrank
`saqeel.css` by construction" was recorded as a *safety* property; this is the
first task where the new CSS had to actually compete, and the property became
the defect.

**The `.sqx-shell*` block was therefore moved out of `@layer sqx.components` and
is now unlayered** (215 rules stay layered, 121 are not). Normal specificity
applies again: `.sqx-shell-nav-item` (0,1,0) beats `a` (0,0,1). This is safe
because those rules only ever match `.sqx-*` classes, which no legacy sheet
targets — there is no rule for them to accidentally override. It is also the
honest structure: the shell *replaces* legacy chrome, whereas T-002's tokens and
component classes were unused and could afford to lose.

The proper fix is still to delete `a { color }` from the frozen sheet, or to wrap
the legacy sheets in a `legacy` layer — both already parked, and either would let
the shell move back inside the layer.

Alongside it, four visual corrections the owner asked for:

- **AI CTA text.** Now `--sqx-on-accent-ai` (white) in **both** themes, and the
  dark gradient changed from the bright pair to the same deep pair as light
  (`#5B3FC7 → #3F2E9E`). White scores 7.05:1 / 10.02:1 on those stops. The
  previous dark treatment — near-black on `#B57BFF`, following the dark-theme
  convention of dark text on bright fills — measured fine at 6.51:1 but was
  reported as unclear, and a deep purple button still separates from the dark
  chrome by 2.20:1 so it does not disappear. `--sqx-accent-ai` stays
  theme-aware for AI *text* on ordinary surfaces.
- **Group headings ("Overview") carry no fill.** The `[data-current]` background
  on `<summary>` was removed; the accent colour went with it. They are eyebrows,
  not controls.
- **A parent gets its fill only when it holds the active child** —
  `.sqx-shell-nav-subgroup:has([aria-current="page"])`. Otherwise no background.
  With the active child, the label is accent on `--sqx-nav-group-bg`
  (7.28:1 light / 7.74:1 dark).
- **Nav rows are neutral, not green.** New `--sqx-nav-text`: light
  `--sqx-warm-1000` (near-black, 16.33:1 worst-case on chrome), dark
  `--sqx-warm-050` (warm white, 14.70:1). They previously used
  `--sqx-text-secondary`, whose dark value `--sqx-ink-300` is green-tinted by
  design. Hover now tints the row with `--sqx-nav-group-bg` and keeps the text
  colour, so hover, parent-of-active and active read as three distinct states.

**10c. Third owner revision — the collapsed rail was broken, from a screenshot.**
The first render anyone has seen of this shell. Five defects, four of them
structural rather than cosmetic:

- **The chevron sat on top of the logo.** `.sqx-shell-rail__head` is
  `justify-content: space-between` with a 28 px brand mark and a 44 px toggle —
  84 px of content with the gap, in a 64 px rail. Collapsed now stacks the head
  into a column.
- **Nav icons were 16 px** (`size="sm"`). Every rail icon moved to `md`
  (18 px), matching the 17 px the legacy `.nav-item svg` used.
- **The vertical rhythm was random.** Hiding `.sqx-shell-nav-group__label` and
  the subgroup label's *contents* left their containers rendering — a 44 px
  empty `<summary>` per group and a 38 px empty label per subgroup, so gaps
  varied by whatever chrome happened to sit above each icon. Collapsed now sets
  `display: none` on the whole `<summary>` and the whole subgroup label, forces
  `.sqx-shell-nav-group__items` to `display: flex` (a closed `<details>` would
  otherwise hide its icons entirely), and applies one uniform
  `gap: var(--sqx-space-2)` across every level.
- **Horizontal scrollbar.** `.sqx-shell-rail` had `overflow-y: auto` and no
  `overflow-x`, and child rows keep a `2rem` inline-start indent that does not
  fit 64 px. Added `overflow-x: hidden`, and collapsed resets the child indent
  and centres every row.
- **"The background colours look weird"** was the browser's default scrollbar —
  a bright light track running the full height of a dark rail. Now
  `scrollbar-width: thin` with `scrollbar-color` from tokens. Badges and the
  restricted-lock glyph are also hidden when collapsed; they had nowhere to go.

**This is the argument for unblocking the dev server, stated as a fact:** every
one of these is obvious in one screenshot and invisible to `tsc`, PostCSS, and
every contrast calculation in this record. The collapsed rail is styled entirely
by `:root[data-shell-rail="collapsed"]`, which no static check exercises.

**10d. Fourth owner revision — parent/child hierarchy. Got it wrong once first.**
The ask was: the child row should be **thinner** than the parent row, and the
child's fill **more** saturated than the parent's. The first attempt instead
wrapped the whole subgroup in a background block — inventing a container nobody
asked for. Reverted; there is no subgroup-level background.

The rule, as it now stands:

| | width | fill |
| --- | --- | --- |
| Parent (subgroup label) | full rail width | soft — `--sqx-nav-parent-bg` |
| Active child | inset both sides | strong — `--sqx-nav-active-bg` |

- `--sqx-nav-parent-bg` applies to the label only when
  `:has([aria-current="page"])`. `--sqx-nav-active-bg` marks the current page and
  is the stronger of the two.
- **Children are inset with `margin-inline`, not `padding-inline-start`.**
  Padding indented the text but left the background spanning the full width, so
  the child's fill reached the same edge as the parent's. Margin makes the
  element itself narrower on both sides — that is what "thinner" required.
- Heights stay equal at `--sqx-touch-target`. "Thinner" is width only; dropping
  a child below 44 px would break WEB-003 §7.
- Collapsed mode zeroes the child margin; there is no hierarchy to show at 64 px.

**10e. Fifth owner revision — the nav highlights are translucent veils, not
solid fills.** "A bit less green, add some opacity." The three rail states are
now alpha over the chrome gradient rather than opaque tints, so the highlight
lets the gradient show through and shifts with it down the rail:

| State | Light | Dark |
| --- | --- | --- |
| hover | `--sqx-shade-050` — ink @ 5 % | `--sqx-glare-050` — warm-050 @ 6 % |
| parent of active | `--sqx-green-veil-soft` — green-800 @ 6 % | `--sqx-neon-veil-soft` — neon-success @ 8 % |
| active | `--sqx-green-veil-strong` — green-800 @ 10 % | `--sqx-neon-veil-strong` — neon-success @ 12 % |

Contrast was measured **composited against each of the three chrome stops**,
because an alpha fill has no fixed colour of its own:

```
                sep vs chrome        accent text on it
light active    1.18 / 1.18 / 1.18   7.33 / 7.62 / 7.27
light parent    1.10 / 1.10 / 1.11   7.85 / 8.17 / 7.74
dark  active    1.32 / 1.27 / 1.24   7.15 / 8.85 / 9.51
dark  parent    1.19 / 1.16 / 1.14   7.93 / 9.67 / 10.40
```

Hover is neutral, parent is a soft green, active is the strongest — three
distinct states with no opaque block anywhere. The five solid tint primitives
this replaced (`--sqx-green-tint-strong`, `--sqx-green-shade-strong`,
`--sqx-green-tint-soft`, `--sqx-green-shade-soft`, `--sqx-ink-tint-group`) and
`--sqx-nav-group-bg` were deleted rather than left as dead near-duplicates.

**When adding any future translucent surface, measure the composite, not the
token.** A `rgba()` fill's contrast depends entirely on what is behind it, and
on this rail that is a three-stop gradient.

Also: **the collapsed rail's toggle now sits above the mark** —
`flex-direction: column-reverse` on the head. The DOM order stays brand-then-
toggle, which is the right reading order; only the visual order flips.

**10f. Sixth owner revision — flat chrome, and the child aligns to its parent's
end edge.** Two changes, one of which reverses a decision from §4.1 of the brief.

**The chrome gradient is gone.** The owner's call: a gradient behind the whole
rail and topbar is wrong; gradients belong on small surfaces — the CTA, labels,
cards when needed. `--sqx-gradient-chrome` is deleted and replaced by a flat
`--sqx-surface-chrome`:

| | chrome (rail · topbar · drawer) | body canvas | card |
| --- | --- | --- | --- |
| light | `#EAF8F0` very light green | `#F7FAF8` | `#FFFFFF` |
| dark | `#001F11` near-black green (`--sqx-green-950`) | `#010A06` | `#05100A` |

The light canvas moved off warm off-white (`#FAF9F6`) onto `#F7FAF8` so the whole
light shell reads green rather than yellow-warm. The dark canvas was left alone:
cards sit at `#05100A`, and lifting the canvas to a stronger green would have
made every card on every page *darker* than the page behind it. That is a
change worth making deliberately with a screenshot, not as a side effect —
parked.

Re-measured after flattening, because every earlier chrome number was a
worst-of-three-stops figure and there is now only one colour:

```
flat chrome text     light 16.51 / 8.41 / 5.70   dark 14.99 / 9.22 / 5.92
canvas text          light 17.20 / 8.76 / 5.94   dark 17.23 / 10.60 / 6.80
nav veil separation  light hover 1.10 parent 1.10 active 1.18
                     dark  hover 1.16 parent 1.18 active 1.30
nav veil accent text light  7.85 / 7.33          dark  9.03 / 8.19
surface separation   light chrome-vs-body 1.04   dark chrome-vs-body 1.15
```

**"Deep green" means near-black green — resolved after two wrong readings.**
Worth writing down so nobody re-runs the search:

| tried | why it failed |
| --- | --- |
| `#0A2A18` (original gradient stop) | desaturated; reads grey-green |
| `--sqx-green-900` `#002D19` | saturated, but only 0.31 contrast-points from the original — the change was invisible |
| `--sqx-green-800` `#00512E` | bright forest green — the *opposite* direction. Needed a whole chrome-specific text ramp to hold contrast, and still put accent text at 4.52:1 |
| `--sqx-green-1000` `#00150C` | 1.06:1 against the body — the rail merges into the page |
| **`--sqx-green-950` `#001F11`** | **chosen.** Pure hue-153 (R=0) so it reads green, near-black, and every standard text token clears its floor with margin |

Because #001F11 is dark, the shell needs **no** chrome-specific text ramp — the
normal `--sqx-text-*` tokens all pass on it, muted included at 5.92:1. That was
not true of the bright-green attempt, which is the clearest signal that going
brighter was wrong.

The dividers stay on `--sqx-border-strong` (2.92:1 dark, 2.95:1 light) and are
load-bearing in both themes: chrome-vs-body separation is 1.15:1 dark and 1.04:1
light, so the border is what draws the edge. `--sqx-border-subtle` scores 1.14:1
on this chrome and would disappear. Do not soften them back.

`--sqx-gradient-cta`, `-ai`, `-signal`, `-edge`, `-sweep` and `-halo` all remain.
Gradients are now confined to the CTA, the active-row edge, and effect classes.

**The child row's end edge aligns with its parent.** `margin-inline-end` was
removed, leaving only `margin-inline-start`. Because both are logical properties,
the inset lands on the leading edge and the trailing edge aligns in **both** LTR
and RTL with no direction rule — which is the entire reason the shell uses
logical properties.

**10g. Seventh owner revision — a crash fix, and CSS Modules are back.**

**The crash.** `shell-topbar.tsx` (server) passed `resultsLabel={count => …}` to
`ShellAdminPalette` (client). Functions cannot cross that boundary, so every
`/admin/*` route threw. Replaced with two template strings, `resultsOne` and
`resultsOther`, interpolated client-side with `{count}`. Swept every other island
for function props — this was the only one. **Worth internalising: `tsc` does not
catch this.** A `(n: number) => string` prop typechecks perfectly and fails only
at runtime, which on this machine means it fails only for the user.

**`saqeel.css` is now tokens only.** Owner decision, reversing the one-stylesheet
rule this same session's T-002 wrote into WEB-002 §6. Component CSS moved to CSS
Modules paired with their components:

Done as a scripted PostCSS extraction with an explicit class map, not by hand —
82 `className` sites rewritten to `styles.*` mechanically, then verified: every
`styles.x` reference resolves to a rule in its own module, and every
`var(--sqx-*)` in every module resolves to a token in `saqeel.css`.

**Two cross-module boundaries had to be broken properly, not papered over.**
A module is scoped, so one component cannot reference another's class:

- The rail's collapsed rules hid `.brandName`, which belongs to `ShellBrand` in
  a different directory. Fixed with data attributes — `[data-brand]` and
  `[data-brand-name]` — which are global and survive scoping. **This is the
  pattern for all future cross-component styling.**
- `ShellMobileNav`'s trigger was styled by the topbar's `.iconButton`. It now
  owns a `.trigger` class in its own module.

**`primitives.module.css` is deliberately unpaired and unimported.** It holds the
190 design-system classes T-002 built — card, button, pill, table, forms,
feedback, navigation — for which **no component exists yet**. Nothing imports it,
so it ships zero bytes. T-006 splits it: each primitive takes its rules into its
own paired module as it is built, and the file shrinks to nothing. Deleting it
now would throw away measured, contrast-verified CSS; leaving it in `saqeel.css`
would have contradicted "tokens only".

**Modules are unlayered.** Same reason as 10b: `saqeel-components.css:15` has an
unlayered `a { color }`, so component CSS must compete on specificity.
`saqeel.css` keeps `@layer sqx.tokens, sqx.base` — the `sqx.components` layer no
longer exists.

**10h. Eighth owner revision — and §6.1's fallback was finally forced.**

**The nav highlight needed a page refresh.** This is the failure the brief
anticipated. `aria-current` was computed on the server from the `x-pathname`
header, but `app/(app)/layout.tsx` is a **persistent layout**: Next does not
re-render it when navigating between its child routes, so `headers()` is read
once, on the first request, and the rail never learns the route changed.
Server-rendered active state is simply incompatible with a persistent layout —
not "hard", incompatible.

**Taking the §6.1 fallback, but narrower than the brief allowed.** The brief
permitted falling back to "one client `shell-rail`". Instead only
`shell-nav-group.tsx` became a client component, reading `usePathname()`. The
rail, brand, topbar and page frame stay Server Components; the client boundary is
five group instances, not the whole sidebar. The server `pathname` prop is kept
as the SSR value so first paint is still correct and hydration matches. Shell
islands: 8 → 9.

**The connector was invisible for every Administration item.** It was gated on
`:has(> [aria-current="page"]:last-child)` — the only position CSS can locate
without knowing the index — and admin hub items are rarely last. Now that the
group is a client component it can *measure* the index, so the subgroup carries

```
data-holds-current  +  style={{ "--sqx-rows-after-active": "<n>" }}
```

and the connector computes its end point:

```css
inset-block-end: calc(
  var(--sqx-rows-after-active, 0) * (var(--sqx-touch-target) + var(--sqx-space-1))
    + var(--sqx-touch-target) / 2
);
```

Exact for any child position, so it works in every hub. A token-valued custom
property through `style` is the one sanctioned use of the prop (WEB-002 §4).
Typed as `CSSProperties & Record<"--sqx-rows-after-active", string>` — no `any`,
no `as unknown as`.

**The active edge cut across the row's rounded corner instead of following it.**
The bar was a 2 px rectangle at `inset-inline-start: 0`. `overflow: hidden` did
clip it to the radius, but clipping a 2 px-wide bar against a 9 px corner just
truncates it — it reads as a straight bar that stops short, not as an edge that
wraps the corner.

First attempt used the CSS gradient-border trick — `::before` filling the row,
`border-radius: inherit`, masked to a start strip with `mask-clip: content-box,
border-box` + `mask-composite: exclude`, keeping the animated gradient. **It made
the bar disappear entirely**, most likely from mixing legacy
`-webkit-mask-composite: xor` with standard `mask-composite: exclude` — they are
different properties, not aliases. Reverted; there are no `mask` declarations in
the shell.

What it is now, and why this shape cannot fail:

```css
.item[aria-current="page"]::before {
  inset: 0;
  border-radius: inherit;
  border-inline-start: var(--sqx-border-width-thick) solid var(--sqx-text-accent);
}
```

A one-sided border on a rounded box renders that edge **including its share of
both corner arcs**, tapering where it meets the zero-width adjacent borders —
which is the crescent the owner asked for. No masks, no compositing, no
multi-layer backgrounds; nothing that can silently produce an empty paint.

**Cost, recorded deliberately: the nav edge is no longer a gradient.** §4.2 of the
brief reserved two animated gradients — this edge and the topbar CTA. A border
colour cannot be a gradient, and `border-image` ignores `border-radius`, so
"curved" and "gradient" are mutually exclusive for a one-sided edge without
masking. Curved won, `--sqx-text-accent` replaces `--sqx-gradient-edge` here, and
the CTA is now the only animated gradient in the shell. `--sqx-gradient-edge` is
still declared and still used by `.edge` in the primitives module.

**10. `features/shell/notification-strings.ts` is a fourth file in a
three-file plan.** `BellStrings` is ~55 lines of translated copy that
`ShellClient` built inline. It was lifted verbatim (comments stripped per
WEB-000 §2) rather than retyped, so not one notification label can drift.
Putting it in `shell-topbar.tsx` would have pushed that file past its budget.
