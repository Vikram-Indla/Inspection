## AR/EN contradictions and document defects found (indexed as written, not resolved)
- **KPI-BR-007 (status-code prefix)** — §4.1.3 "الحالات" (Statuses) table uses codes `F020`/`F021` (the same `F`-prefix pattern used for *services* in §4.1.2, e.g. F001/F002) instead of a status-specific prefix (contrast ITM.md's ST001-ST005). Both rows are otherwise blank (no status name, description, or user filled in for either language) — the entire Statuses table is unpopulated in the source.
- **KPI-BR-006 (services table F001/F002 blank)** and **KPI-BR-008 (permissions matrix blank)** — §4.1.2 "الخدمة" and §4.1.4 "مصفوفة الصلاحيات" tables have header rows only; no service name/description/users or permission-matrix values were filled in for either service row or any of the 4 listed user roles (مدير الفرع / مدير القطاع / المسؤول / اللجنة). Indexed as a gap, not invented.
- **"المحدادت" heading typo** — every one of the 9 report filter tables in §5.2.1-5.2.9 uses the misspelled Arabic heading "المحدادت" (should be "المحددات", i.e. "Filters/Determinants"). Appears identically at the top of each filter block; flagged once here, not repeated per BR row.
- **KPI-BR-254..269 (Targeting Report §5.2.5 notes-column row-shift)** — throughout the §5.2.5 filter field table, the "Notes" column text describing a given field's meaning is offset by one row: the note that semantically describes field N ("Target Name") actually sits in field N's own row but reads like a description of the *next* field ("Targeting Start Date"), and this shift repeats for every subsequent row in that table (source lines 2068-2147). Indexed exactly as written per field below; the apparent misalignment is not resolved. Notably, the equivalent §5.2.5 grid-column table (lines 2161-2242) does NOT exhibit this shift — its Notes column is simply empty throughout.
- **KPI-BR-128/KPI-BR-130 (platform name spelling: "Sanayi" vs "Sanaii")** — UC002's "System Environment" field (English) reads "Sanayi Platform" but UC002 BC004 (English) reads "...as defined in the compliance systems and Sanaii platform..." — the same Arabic term "منصة صناعي" is translated two different ways ("Sanayi" / "Sanaii") within the same use case.
- **KPI-BR-014 (EN BC005 adds unattested qualifier)** — UC001 BC005 Arabic: "يتم احتساب الموشرات في البنود على البنود المنطبقة فقط" (indicators on items are calculated on applicable items only). English BC005 renders this as "Indicators are calculated only on applicable items according to the relevant business logic" — the English adds "according to the relevant business logic," a qualifier with no Arabic counterpart.
- **KPI-BR-035 (Administrative/Management-notes indicator title has a stray parenthesis)** — §5.1.2 row "الالتزام )الملاحظات الادارية)" (sic — opening paren is missing, closing paren duplicated) vs English "Management notes"; indexed verbatim.
- **KPI-BR-213/KPI-BR-218 and KPI-BR-237 (field-label mismatch: "المنطقة"/Region vs "Department/Branch")** — in the §5.2.3 Inspector Performance and §5.2.4 Complaints filter/grid tables, the Arabic field label is "المنطقة" (Region) but the paired English label given is "Department/Branch" — a different concept in English than what the Arabic names. Indexed as written, not resolved.
- Every one of the four dashboard panels (§5.1.2-5.1.5) that carries a "Drill down" / "الإجراءات" sub-block repeats the *identical* 11-field drill-down column set (Facility name, Facility ID, Facility status, Region, Activity, Last visit date, Compliance Status, Matching Items Count, Non-Compliance Items, Risk level, Visit Type) plus an Export action verbatim, except §5.1.5 (External Entities), whose drill-down set is a shorter 6-field subset (no Last visit date, Matching/Non-Compliance Items Count, Risk level, or Visit Type).
