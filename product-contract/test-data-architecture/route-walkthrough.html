Four tiles are still empty, and that needs your decision

The three above are now populated, because publishing a policy version is test data like any other row. The seed carries test values marked as such — a 12-month cycle, an 80% target, a 75% SLA warning — all editable in policies.csv and all needing business sign-off before real use.

The remaining four need code, not data. Violation trend needs an issued_at column on violations. Risk distribution needs a Health Score snapshot source. Licence exposure and Repeat violation rate need a policy parameter plus a change to the projection that reads it. Two additive migrations and one projection change would fill all four. That is application work, which this session is not authorised to do — say the word and it becomes the next task.

Simulation

How you see this before anything is loaded

  1. You are looking at it. Every number on this page was computed by build_cohort.py from the generated cohort. No database was touched.
  2. The cohort is three files. factories.csv (73), personas.csv (45), journeys.csv (300). Open them, change a name, re-run the script, and this page changes with them.
  3. Nothing is random. The generator uses no clock and no random seed. The same inputs always produce the same 300 journeys, so the demo is identical every time you run it.
  4. Then it loads. Once you approve the shape, the loader writes these rows through the real application paths so the audit trail is genuine, and the unload script removes them by exact row ID.

Cohort: seed-source/journeys.csv · personas.csv · factories.csv · Figures: seed-source/route-preview.json · Regenerate: python3 build_cohort.py · No database has been written to.
