## The headline

**The inspection journey completes for the first time.** Walked end to end
today with real accounts, on a chain created for the purpose:

plan → approve → release → check in → carry out the inspection → record a
non-compliance → attach the corrective form → submit → **supervisor returns it
for correction** → inspector corrects and **resubmits** → supervisor approves
version 2 → **the visit closes**.

Verified in the data, not from a report: two submission versions on the record,
the inspection approved, the visit closed by the trigger without a separate
action, one completed corrective action form.

Nobody had ever seen the second half of that sequence work.

## What B2 adds over B1

**Four governed rules, applied live and verified by querying the objects:**

- A corrective action form is required **only when a violation or non-compliant
  answer exists**. Previously demanded on every submission, trapping any
  inspection using such a package.
- **A visit closes when its inspection is approved.** The lifecycle had no
  terminal state at all — no visit could ever be finished. The backfill closed
  the eight already stranded.
- **Operations reads use the four real roles.** The rule named five, of which
  one existed, so almost everyone was refused.
- **Administrators can see Planning and the Operations Centre**, view only.

**Three faults in the inspector's offline path**, all of the same family and
all found by walking:

- A submission refusal was replayed silently every eight seconds forever while
  the screen said "queued". A refusal now leaves the queue and says what
  happened.
- The pre-submit check was **stricter than the server it mirrors**, refusing
  submissions the database would accept.
- The queue paired each item with the wrong key, so a resubmission threw and
  **stopped the entire queue** — stranding every other pending item.

**Eleven reported defects** from Sujatha Sista and Sikander Ahmad: the
regulations list as a table, Deactivate no longer offered on a draft, duplicate
links, the access screen named consistently, Arabic no longer shown to English
readers on three screens, the sign-in screen no longer flashing on refresh, the
Factory 360 skeleton matching its layout.

**More internal vocabulary removed**, including three identifier codes the
first sweep missed because they used different classes.

## What B2 does NOT contain

- **Sixty-seven permission rules still refuse everybody.** Eleven role names
  are used that do not exist in the database; B1 and B2 together fix only those
  that were blocking reported work. This is the largest open risk.
- **Jira does not stand on its own.** Three of nine requirement documents
  indexed. A tester still cannot work from the stories alone.
- **The design file is largely uncorrected.**
- **Thirteen approved designs were never built. Twenty-two administration
  screens have no design.**
- **The reviewer screen still shows "Resubmission blocked"** when resubmission
  now works. Stale, harmless, not yet fixed.
- **A confirmed non-compliance does not create a violation record.** The
  corrective-form rule fires correctly on the non-compliant answer, so nothing
  is broken in this build — but whether a violation should be raised is an open
  question for the Product Owner.
- **No corrective-form entry screen exists for package-level forms.** A form
  added manually is written with empty fields and then fails the completeness
  check. Only the per-item path can supply one.
- **Twelve Arabic labels** await native review. **Dark values for the role
  colours** are not decided.

## Known limits of the proof

The walk disclosed every substitution: location was simulated (no satellite
signal in that environment), the photograph was synthetic, the signature was
drawn with a mouse. Those are environment limits, not platform behaviour.

Step 07 was proven on a package with real checklist items. The earlier clean-run
proof used a package with none.

## What testers should do

Test the whole journey, including the correction leg. Test compliance,
enforcement, administration, and the wording everywhere.

Report any text that reads as though written for an engineer — that is a defect
now, not a detail.
