## NOT DEPLOYED, AND WHY

**Two screens do not respond to clicks when opened directly.** Both are in this
build and both are known:

- **The review record.** Proven inert — the tab bar renders and does nothing.
  Reachable by administrators, supervisors, planners and the assigned inspector.
- **The package draft editor.** Not verified, and possibly worse — it carries 25
  interactive controls. If it is inert, adding an item, saving a draft and
  publishing are all dead. Nobody has been able to open it: it needs an
  administrator session, and no lane may enter a password.

A tester who reaches either by pasting a URL or refreshing sees a page that
looks correct and does nothing. Deploying without saying so would produce
exactly the contradictory reports that cost a day.

## What B4 adds over B3.1

**Two outages from one underlying mistake, both fixed**

Values that cannot cross from the server into a client component were being
passed anyway. Two entirely different symptoms, one cause:

- **The planning map was blank.** Two formatting functions crossed the boundary
  and the render threw. Counts now cross as text templates and are filled in on
  the client side. Verified on a deployed build: the panel reads "6 unassigned
  visits", so the numbers work — not merely that the crash stopped.
- **The review record is inert.** Seven server-rendered panels cross as a prop.
  Root-caused and proven by experiment; the fix is a decision about that
  component's contract and has not been made.

**The map, which was three faults wearing one message**

The live map section set no height, so it collapsed to a single pixel. A map
with no size never finishes loading, so a timer expired and the panel announced
"basemap provider failed" — sending three separate investigations after the
network. The same missing height also broke the operations map region and
Factory 360's "View on map".

The design system already contained the correct height rule, defined and used
nowhere.

**Correctness**

- The monospace font named no Arabic family, so Arabic inside any monospaced
  element fell to an arbitrary system face. In an Arabic-first product that is a
  correctness fault, not a preference. Latin stays monospaced; Arabic now uses
  the application face.
- Risk band rendered as bare lowercase text beside a numeric score. Status must
  never be colour or text alone; it is now a badge, matching the visit status
  already on the same screen.
- The application manifest and favicon were pinned to whatever a browser first
  fetched, for the life of the cache. Now fetched fresh with an offline
  fallback.

**Removed rather than fixed**

The manual add-a-corrective-form route. Three mentions across 1,354 requirements
and every one is an optional text field on a violation — never a standalone form
a user creates. It produced records guaranteed to fail their own completeness
check, and it obstructed the working route it appeared to support.

**Also**

"Primary navigation" no longer prints as visible text on every administration
route. The explorer row labels no longer render as links.

## Deliberately not fixed

- **Bulk violation issuance** is switched on, can issue real penalties, has
  never been exercised end to end, and **no requirement asks for it.**
- Supervisors can still reach administration screens — a governance conflict,
  not a defect.
- The administration top bar overlap and the sidebar clipping long labels: both
  need an administrator session to reproduce.
- Three colour-law violations inside the design system. **No token expresses
  "the same in both themes"** and none may be invented — a design-system gap.
- The location-events read discards its error, so a failed read silently shows
  fewer points.
- Twelve Arabic labels await native review; dark values for the role colours are
  undecided.
- Sixty-seven permission rules still refuse everybody. All are write rules.

## What was searched, and what was not

A sweep for values that cannot cross the server/client boundary found three
instances of rendered content crossing, zero functions, zero other
non-serialisable values.

**The first attempt produced 155 candidates and missed both known outages.** It
was discarded. The detectors were rebuilt to scan where the fault appears and
validated against the broken code first, so each is known to catch its own
offender.

**Not covered, stated so the list is not mistaken for completeness:** props
assembled into an object before being passed — the detector for that has no
positive control, so zero means "not detected" rather than "not present" —
spread props, components reached indirectly, and props built in helper files.
