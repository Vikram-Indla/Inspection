## What B3 is

A consolidation. Every lane's work gathered onto one verified commit, so that
"is it in?" is answered by a tag rather than by asking five people.

Five separate lanes were each holding finished work nobody could see. That is
the single most expensive habit of the day and B3 exists to end it.

## READ THIS BEFORE TESTING

**Bulk violations can now issue real violations.** The screen had a hardcoded
flag refusing every submission while the capability behind it was deployed and
working. The flag is gone. It is role-gated, acknowledgement-gated and validated
server-side — but **the end-to-end path has never been exercised**, because
doing so creates real violation and inspection records. Test it deliberately,
against a throwaway factory, or not at all.

**Test a build of B3.** Every screenshot reviewed today came from a workspace
that carries none of this. Testing anything older will re-find defects that are
already fixed, which has already cost a day.

## What B3 adds over B2

**Two screens that could not be used at all**

- Bulk violations refused every submission, as above.
- The compliance explorer shipped as a four-column table when the approved
  design is a column of rows where the whole row drills. Rebuilt to the design's
  structure, existing classes only.

**One fault behind several complaints**

The approved design carries a global link reset. The application never had one —
only per-component resets — so every link fell back to the browser's underline,
including links wearing classes that assume none. That single omission is why
both "the tabs look weak" reports looked broken. Ported.

**Sujatha's remaining defects**

Packages list collapses by default. The items catalogue clause reference now
opens the source regulation record rather than the list. Record tabs scroll
inline with the count badged.

**More internal vocabulary removed** — 23 strings across 11 files: specification
references, database table names rendered inline in sentences, an internal role
name on a button label.

**A wrong diagnosis corrected.** The map reported "not configured" for maps that
had in fact failed to load. Two different problems, one message.

**Governance**

- DEC-032 closed. It had been recorded as an open P0 reading "blocks ALL real
  inspection submissions" for four days after it was fixed.
- Request and Order Management ruled out of scope, with what is deliberately
  unbuilt written down so nobody rediscovers it as a defect.
- Where a requirement's Arabic and English disagree, the Arabic prevails —
  except where following it would widen a permission, and there the narrow
  reading holds.
- The write-policy audit, including which permission rules guard capabilities
  with no screen behind them. Those need no ruling at all.

## The requirements index — read the caveat, not the number

Nine documents indexed. **Three had use-case structures that did not match their
source text**: Items claimed 16 use cases where the source has 3, KPIs claimed
19 where the source has 2, Visit Management claimed 13 where the source has 2.
Those identifiers were invented, and stories were written citing them.

Items and Systems are corrected and verified. KPIs, Visit Management, External
Users and Inspection Service are being re-extracted.

**No coverage figure is trustworthy yet, and the totals row is struck through in
the index itself.** Two numbers were quoted today — 894 and 968 — and both were
built on documents whose structure had not been checked. There will not be a
third until every document is confirmed.

## Capabilities built with no requirement behind them

Found while grounding stories. Each needs a decision — keep, or drop:

- Localization and governed strings
- The integration and endpoint registry
- Delegated execution — an inspector temporarily handing execution to a
  substitute
- Package preview and pre-approval impact review

## What B3 does NOT contain

- **Sixty-seven permission rules still refuse everybody**, all of them write
  rules that decide who may change something. The read rules are fixed. The
  write rules need the Product Owner's rulings and the audit table is ready.
- **Supervisors can still reach administration screens.** The Product Owner says
  they must not; a change control deliberately put them there to reach three
  destinations with no other route. A governance conflict, not a defect.
- **The administration top bar overlaps the sidebar**, and a control is clipped
  behind it.
- **"Primary navigation" renders as visible text** in the administration top bar
  — an accessibility landmark name shown as interface copy.
- **The sidebar clips long labels mid-word** and has no collapse control, though
  the mechanism exists and works on the main shell.
- **Error codes remain in field-facing messages.** Deliberate: an inspector
  quoting one to support is using it. Open for a ruling.
- **Three colour-law violations inside the design system itself.**
- **The card shadow dispute** is unresolved by choice — it comes from a shared
  style, and changing it to fix one screen would alter every card.
- Twelve Arabic labels await native review. Dark values for the role colours are
  undecided.

## The method, stated once

Every fix that failed today came from acting on a description without measuring
first — three design regressions, four defects called from shape, two
requirement totals repeated without asking how they were built.

Every fix that held came from looking at the actual thing: the code, the
rendered frame, the database, or the journey walked end to end.
