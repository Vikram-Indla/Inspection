## What B5 adds over B4.1

**A governed rule that existed only on paper is now in the product**

A violation can no longer be recorded against a facility that is not in
production. Enforced in the database, so an offline or stale device cannot get
around it, and the inspector sees the real reason rather than "save failed". A
refusal on a business rule is never queued for retry — the offline queue
freezing on a permanent refusal is a defect already fixed once today elsewhere.

Proved in all three directions against the live database before any test was
written, then rolled back with nothing persisted.

**Two limits of that gate, stated rather than discovered later**

- The written rule covers data-mismatch violations. The gate refuses **every**
  violation. Nothing breaks today — the only other violation type is not built
  — but it is wider than the requirement and needs a ruling.
- A facility whose status has not been answered is allowed through. Deliberate:
  the alternative retroactively blocks every inspection recorded before today.

**Eighty per cent of notifications were showing a machine identifier**

Four planning events carried no label at all, so they printed their raw event
key to the user — 838 of roughly 1,041 notifications on record. Labelled in
both languages.

**The account menu read as body text.** Identity, attributes and actions are now
three separated groups using the menu classes the design system already carried
and nothing had used.

**A requirement identifier reached an inspector.** The new refusal message
quoted its governing rule number on screen. Removed from the screen, kept in the
code comments. An inspector cannot act on a requirement identifier, and quoting
one to support is the pattern removed from ~256 places today.

## Still not fixed, and honest about it

**The review record does not respond to interaction in the production build.**
Cause unknown. Three hypotheses eliminated: the panel prop shape, the children
contract, and the component itself — it is fully interactive in a development
build of identical source, with no error, warning or exception logged. Nobody
has examined the production build path. It is not close to fixed.

Reaching the record by clicking through the queue works. Only a pasted URL or a
refresh produces the dead tab bar. Testers must be told, because the two routes
give opposite results and that pattern has already produced a day of
contradictory reports.

**The package draft editor is unassessed, not broken.** No lane could reach it —
a supervisor session is refused by the route, and no lane may enter a password.
Twenty-five interactive controls are unverified. It needs an administrator
sign-in to establish either way. Do not record it as broken; nobody has evidence
either way.

**Bulk violation issuance** is switched on, can issue real penalties, has never
been exercised end to end, and no requirement asks for it.

**Sixty-seven permission rules still refuse everybody**, all write rules.

**Colour-law violations in the shell**, pre-existing, introduced by the
responsive chrome work — hardcoded values with token fallbacks. Not from today's
changes.

**A design-system gap, not a page defect.** The field workspace card has no class
for its own padding and spacing, so it is inlined in several places. The shell
menu had the same problem and the classes turned out to exist; the field
workspace's may not. Reported as a change request per the rules, not worked
around.

Twelve Arabic labels await native review. Dark values for the role colours are
undecided.
