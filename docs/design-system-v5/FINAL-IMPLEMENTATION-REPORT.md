## What's NOT done, and why
- **Real-device iPad hardware testing** (physical Split View, Apple Pencil, actual touch). This is a hard environmental limit, not a scope choice. Checked directly rather than assumed: `.env.local`, `package.json`, and `playwright.config.ts` were grepped for BrowserStack/Sauce Labs/LambdaTest credentials — none exist, so no device-lab service is provisioned in this environment, and none can be provisioned by continuing to write code here. Two levels of evidence short of physical hardware were captured, honestly labelled as such:
  1. Browser-viewport screenshots at iPad dimensions (1194×834 landscape, 834×1194 portrait) — confirm layout/reflow correctness.
  2. `apps/web/scripts/verify-touch-targets.mjs` (new) — uses Playwright's real `devices['iPad Pro 11']` descriptors (actual device pixel ratio, Mobile Safari UA, `hasTouch: true` touch-context), authenticated as the inspector persona, and measures `getBoundingClientRect()` on the Wave 6 touch-target fix (the field-home view switch) without tapping/mutating any seeded data. Result: **6/6 controls ≥48px** in both orientations under real touch-context device emulation — one step closer to hardware truth than a bare desktop-viewport screenshot, but still Chromium's touch *emulation*, not physical Apple Pencil/multi-touch hardware. The other Wave 6 fixes (ImageAnnotator tool switch, Workspace/GatedRepeater Yes/No toggles, Startup checkboxes) sit deeper in stateful field workflows where an automated tap risks mutating the one set of seeded evidence data other checks depend on, so they were left at the screenshot-only evidence level rather than scripting taps that could corrupt shared fixtures.
  Closing this item fully requires a physical device or an external device-lab service (e.g. BrowserStack App Live / a real iPad in-hand) — outside this session's environment, not outside more effort.
- Print-fixture tests (1/20/100/300 items, no-violations, many-violations, long-Arabic-notes, missing-signature, multiple-versions, invalid-approval) — no test harness for these exists in this repo; the one real submitted inspection captured has a small item set and no violations, so it doesn't exercise the larger/edge-case fixtures.
