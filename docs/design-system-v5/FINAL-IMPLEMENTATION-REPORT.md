## What's NOT done, and why
- **The report/print 5-layer content-model rebuild** the spec describes (identity/outcome, findings/compliance, violations/corrective-actions, evidence/versions/decisions/lineage, acknowledgement/signatures/legal-footer as five distinct governed layers). The existing single-page-with-sections structure was kept and its print CSS corrected, not restructured. This is a deliberate boundary, not an oversight: the print-preview screenshot confirms the current structure already renders correctly end-to-end (bilingual header, compliance table, signature block, all correct); restructuring the content model of a legally-significant government inspection report is a different, larger kind of change — closer to a product redesign than a design-system application — and carries real risk of introducing content-correctness bugs (e.g. around the DEF-WF-006 invalid-approval block or immutable-snapshot semantics, neither of which this session touched or re-verified) for a benefit that isn't yet demonstrated to be necessary.
- **Real-device iPad hardware testing** (physical Split View, Apple Pencil, actual touch). This is a hard environmental limit, not a scope choice — no physical device or device-lab access was available. Browser-viewport screenshots at iPad dimensions (1194×834 landscape, 834×1194 portrait) confirm layout/reflow correctness, which is what's achievable without hardware.
- Print-fixture tests (1/20/100/300 items, no-violations, many-violations, long-Arabic-notes, missing-signature, multiple-versions, invalid-approval) — no test harness for these exists in this repo; the one real submitted inspection captured has a small item set and no violations, so it doesn't exercise the larger/edge-case fixtures.
- A formal manual visual-acceptance review of the 18 captured screenshots against a checklist, and a manual screen-reader (VoiceOver/NVDA/JAWS) pass — the sponsor's stated next step is an independent ChatGPT Work 25+ screen audit, which this session's evidence feeds into but doesn't substitute for.
- `:has()` CSS selector browser-support verification for the search-icon self-suppression logic, beyond what's confirmed working in the Chromium-based screenshots.
