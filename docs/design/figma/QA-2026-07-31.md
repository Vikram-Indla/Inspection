## Root causes found

### 1. Planning tables crushed text — the CSS forbids what we built
`saqeel-components.css:154-160`:

```
/* …at intrinsic width and scroll the bounded region instead of crushing text. */
.planning-visit-table { inline-size: max-content; min-inline-size: 100%; }
.planning-visit-table th, td { white-space: nowrap; }
```

Figma had 13 equal 76px columns, breaking 10-digit CR numbers mid-word. **Session 11's
conclusion that "the design has the same equal-column constraint" was wrong for Planning** —
that class exists specifically to prevent this. Corrected to intrinsic per-column widths with a
clipping wrapper: Planning columns now `72/166/88/79/138/76/110/79/95/95/62/127/88` = 1275 in a
992 wrapper, which is exactly `max-content` + `overflow:auto`.

Applied to Analytics, Enforcement, Compliance and Execution too. Where intrinsic total is *under*
the wrapper (Analytics, 530 of 992) the columns scale up proportionally, matching `.table { width:100% }`.

### 2. Button typography was wrong on all 60 variants
- `.btn` sets `line-height: 1` (`:11`); Figma had 135% / 145% / AUTO.
- `--type-button-w: 500` (Medium); the Medium variant rendered **Regular**.
- The Large variant's 14px was unbound.

Note `--type-button-size` is **13px** at `tokens.css:235`; the 14px at `:311` is the
`[data-density="field"]` override — the same wrong-branch trap as the session-10
`type-compact-size` bug. Sizes are now bound to `type-label-size` / `type-button-size` /
`type-body-size` (all value-exact per `.btn-sm :31`, `.btn :10`, `.btn-lg :32`), weight Medium,
line-height 100%.

### 3. The createAutoLayout white-fill bug was never swept outside the screens
Sessions 3-4 cleared 1,376 stray white fills on the screens page only. The Foundations and
component pages still carried ~200 — invisible on a light canvas, solid white blocks in dark mode.
All cleared.

### 4. Arabic had no text styles at all — by construction
Swapping the font family to Noto Sans Arabic drops the style link, so all 4,992 AR text nodes were
literal. Applying the Latin `t-*` styles would revert the font. **Fixed structurally:** a new
Arabic ramp — `t-display-ar` … `t-metric-ar` (11 styles, Noto Sans Arabic, same sizes and
line-heights as their Latin counterparts). 4,982 nodes now carry a style. The AR screens are
maintainable for the first time.

### 5. Figma instances silently drop paint-level opacity
Setting `fill.opacity = 0.08` on a component renders at `1.0` in every instance, while the
component still *reads back* 0.08 — so a property audit passes while the canvas is wrong. Every
`color-mix(…, transparent)` in `admin-shell.css` is now a **derived colour variable carrying the
alpha** (`ad-state-error-bg`, `ad-cmdk-bg`, `ad-util-bg`, …). Variables do propagate to instances.
Tints must be verified by sampling rendered pixels, not by reading node properties.

## Deliberately not changed

- **`map-cluster`** keeps 2 unbound paints. It mirrors a real code bug
  (`saqeel-components.css:363` — `background: var(--nav-bg)` with a hardcoded `color:#fff`,
  invisible in light theme). Locked decision: mirror, do not silently fix.
- **Wordmark brand art** keeps its own hex (`#0d8f63`/`#1d1f20` light, `#34d399`/`#ffffff` dark)
  per DEC-011. The asset README requires swapping the two files by theme, never recolouring, so
  it is modelled as a `Theme` variant.
- **8 EN text nodes without a style**: 6 are `seg-label` at 12px/600 — the design's own measured
  rendering (`fw=600` on the active segment) and no 12px SemiBold token exists; 1 has mixed fonts;
  1 is `brief-body`.
- **10 AR nodes without a style**: 12.5px mono `id-code`. There is no Arabic mono face.
